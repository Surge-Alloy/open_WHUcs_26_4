## 🛠 如何更改 / 更新仓库内容

仓库本体就是一堆普通文件，**改内容不外乎三种办法**，按改动大小挑一种即可。下面前两种都能完成 90% 的日常操作。

### 方式一：GitHub 网页端

适合：改 README 文字、传一份课件/试卷、顺手建个目录。

1. 打开仓库首页：<https://github.com/Surge-Alloy/open_WHUcs_26_4>
2. **改已有文件**：点进文件 → 右上角铅笔 ✏️ 图标 `Edit` → 直接编辑 → 点 `Commit changes` → 写提交说明（如 `docs: 补充高数期中考点`）→ 再点 `Commit changes`。
3. **新增文件**：进入目标文件夹 → 右上 `Add file` → `Upload files`（把文件/整个文件夹拖进去，会保留内部目录层级）或 `Create new file`（新建空文件）。
   * 新建时文件名里可以直接用 `/` 建目录，例如输入 `大一上学期/高等数学/复习笔记/极限与连续-张三.md` 就能一步建好三层路径。
   * 想建一个**空文件夹**：该目录里放一个 `.gitkeep` 空文件即可（Git 不跟踪空目录，约定俗成用这个占位）。
4. **删除文件**：点进文件 → 右上 `…` → `Delete file` → `Commit changes`。
5. **重命名 / 移动文件**：点开文件 → 铅笔旁的下拉箭头 → `Rename file`，文件名里带上新路径即可移动。

> ⚠️ 网页端单文件上传上限 **25 MB**；拖文件夹上传时不要拖太多大文件，容易中途失败，大文件请走网盘链接（见「注意事项」）。
> 没有写权限的账号会被拒绝，先看下面的「如何贡献」走 Fork + PR，或找管理员把账号加进 Collaborator。

### 方式二：本地 Git 命令行

适合：一次传几十个文件、批量改名、长期维护、本地能直接编译/预览。

**① 一次性配置身份**（每台电脑做一次就行）：

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
# 建议用 GitHub 的隐私邮箱：数字ID+用户名@users.noreply.github.com
```

**② 首次克隆**（之后在同一个文件夹里工作，不用再 clone）：

```bash
git clone https://github.com/Surge-Alloy/open_WHUcs_26_4.git
cd open_WHUcs_26_4
```

**③ 日常一轮：先拉取 → 改文件 → 查看 → 暂存 → 提交 → 推送**

```bash
git pull                      # 1. 先同步别人的改动，避免推送被拒
# ...2. 把资料放进对应目录，或用编辑器改 README...
git status                    # 3. 看清楚了哪些文件被改/新增/删除
git add .                     # 4. 全部暂存；只提交某个文件就写 git add 路径/文件名
git commit -m "docs: 添加-复习笔记-高数-极限部分-张三"   # 5. 写清改了什么
git push                      # 6. 推送到 GitHub
```

**④ 首次 push 的登录方式（二选一）**

* **HTTPS + Personal Access Token（最省事）**：GitHub 右上头像 → `Settings` → `Developer settings` → `Personal access tokens` → `Tokens (classic)` → `Generate new token`，勾上 `repo` 权限 → 复制 token。push 时用户名填 GitHub 用户名，密码处**粘贴 token**（GitHub 早已不支持账号密码）。token 等于密码，别外传、别写进代码。
* **SSH 密钥**：`ssh-keygen -t ed25519 -C "你的邮箱"` 一路回车 → 把 `~/.ssh/id_ed25519.pub` 的内容贴到 GitHub → `Settings` → `SSH and GPG keys` → `New SSH key` → 然后 `git remote set-url origin git@github.com:Surge-Alloy/open_WHUcs_26_4.git`。
* Windows 装了 Git 自带 **Git Credential Manager**，第一次 push 会弹浏览器登录一次，之后自动记住，通常不需要手动配 token。

### 方式三：图形界面

* **GitHub Desktop**：`File` → `Clone repository` → 选 `Surge-Alloy/open_WHUcs_26_4` → 本地直接用资源管理器改文件 → 左侧 `Changes` 里核对 → 左下填 Summary → `Commit to main` → 右上 `Push origin`。
* **VS Code**：打开克隆下来的文件夹 → `Ctrl+Shift+G` 打开「源代码管理」→ 改完文件后会列在 `Changes` 里 → 点文件旁的 `+` 暂存 → 输入提交说明 → 点 `✓ Commit` → 点左下角 `Sync Changes`（或 `...` → `Push`）。

### 改之前先对一下：文件该放哪

* **按路径放**：`学期 / 课程 / 资料类型`，例如 `大一上学期/线性代数/往年真题/`；缺什么目录就新建（记得补 `.gitkeep`）。
* **按规范命名**：`[资料类型]-[简述/作者]-[年份]`，例：`期末真题-线代-2025年.pdf`、`复习笔记-C++-指针与引用-李四.pdf`。
* **只改自己负责的内容**：要覆盖或重命名别人传的资料，先在群里吱一声，别互相踩。
* **改了结构记得同步 README**：新增课程/新资料类型时，把上方「本学期课程」表格和「目录结构」目录树一起改掉，否则后来人会找不到。

### 常见问题排查

| 现象 | 原因 | 解决 |
| :--- | :--- | :--- |
| `push` 报 `[rejected] ... (fetch first)` | 远端有别人新提交，你本地落后 | 先 `git pull`（冲突就手动合并 → `git add` → `git commit`），再 `git push` |
| 输入密码总提示认证失败 | GitHub 已禁用账号密码推送 | 改用 Token 或 SSH（见方式二 ④） |
| 空文件夹推上去不见了 | Git 不跟踪空目录 | 目录里放 `.gitkeep` |
| 上传大文件失败 | 网页 25 MB / 仓库体积限制 | 传网盘，仓库里放 `.md` 记录链接+提取码；必要时用 Git LFS |
| 网页改了 README，本地 `pull` 冲突 | 同一行两边都改过 | 打开冲突文件按 `<<<<<<<` 标记保留需要的部分，删掉标记后 `git add` + `git commit` |
| 想撤销还没提交的修改 | — | `git restore 文件名`（全部撤销用 `git restore .`） |
| 提交错了想反悔（还没 push） | — | `git reset --soft HEAD~1` 回到提交前，改完重新提交 |
| 改完 README 页面还是旧的 | 浏览器缓存 | `Ctrl + F5` 强制刷新 |

## 🤝 如何贡献（Contribute）

非常欢迎且鼓励大家分享优质资料！为了保证仓库的可持续性，请遵循以下规范：

### 1. 文件命名规范
请尽量做到“见名知意”，建议格式：`[资料类型]-[简述/作者]-[年份]`
*   ✅ 优秀示例：`期末真题-高数-2025年.pdf` / `复习笔记-线代-张三整理.pdf` / `上机实验-C++-第3次.zip`
*   ❌ 拒绝示例：`新建文件夹.zip` / `资料.pdf` / `最终版最终版(2).doc`

### 2. 提交方式（Pull Request）
如果你没有直接 Push 的权限：
1. Fork 本仓库到你的个人 GitHub 账号。
2. 在你的仓库中建立新分支（如 `add-math-notes`），上传资料。
3. 回到本仓库发起 **Pull Request**，并在描述中简要说明你添加了什么资料。
4. 仓库管理员审核后会进行 Merge。

如果你有直接权限，请尽量使用 `git commit -m "docs: 添加高数期中复习笔记"` 这种清晰的 Commit 信息。

## ⚠️ 注意事项与免责声明

1. **版权与隐私**：请**不要**上传老师明确禁止外传的内部资料、考卷，或包含个人隐私（如包含全班身份证号、成绩单原表等）的文件。
2. **拒绝大文件直接上传**：如果资料包含大量视频教程或巨大的数据集，建议**使用百度网盘/阿里云盘链接**，并在仓库中创建一个 `.md` 文件记录链接和提取码，避免撑爆 GitHub 仓库。
3. **代码规范**：上传代码作业时，请附带简单的注释或 README 说明环境配置与编译方式（如 C++ 请注明编译器版本与编译命令），方便他人参考。
4. **学习为本**：本仓库仅供班级内部学习交流与参考，**请勿直接照抄作业或实验代码**，学术诚信是底线哦！
